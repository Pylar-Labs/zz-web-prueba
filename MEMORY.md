## Aprendizajes y errores a evitar
- GateGuard bloquea el primer Write/Edit de cada archivo y los comandos "destructivos" (`rm`, `git reset --hard`, incluso un cuerpo de PR que cite comandos de borrado): presentar los hechos con reversión en una línea y reintentar. En lotes paralelos solo falla el primero de cada archivo: comprobar cuál.
- **Verificar mis propias consultas:** `gh ... state=all` no es válido, `/tmp` de Bash no es el de Node en Windows y `grep -c $'\r'` cuenta todas las líneas aquí: contar bytes con node. Si una prueba "no falla", comprobar que el cambio se aplicó de verdad.
- `core.autocrlf=true` sin política dejaba los documentos en CRLF al clonar y como `M` aunque fueran idénticos. Con `.gitattributes` ya no; en un clon anterior: borrar los dos y `git checkout --` (ver `AGENTS.md`).
- `z.enum` informa todo valor inválido como `invalid_value` (incluso `null`): separar por tipo al traducir el error.
- Barrera por idioma: buscar por palabra completa, quitar direcciones de correo y no cortar la URL de WhatsApp en `'`.
- `npx -y node@22.23.4` puede ejecutar otro Node: comprobar `process.version`. Un build puede fallar `check-dist` si hay builds encadenados (una vez, no reproducible): repetirlo solo.
- Un `npm ci` limpio sin commits: copiar `git ls-files -co --exclude-standard` a una carpeta temporal.
- Astro no deja abrir un segundo `dev` o `preview`: quedan los de sesiones anteriores (4321, 4431, 4432); no matarlos.
- Sin lockfile, npm falla con `EALLOWREMOTE` por un paquete wasm de Tailwind.
- Diseño: medir con iframes de cada ancho en una página de medición (una ejecución por build), no con muchas navegaciones; en iframes hay barra de 15 px (más exigente que el móvil). `break-words` no reduce el ancho mínimo de un texto sin espacios en una columna centrada: usar `wrap-anywhere`. `min-w-0 truncate` + `shrink-0` en el resto mantiene la cabecera en una línea.
- Tipos: `Record<string, F>` finge que toda clave existe (declarar `F | undefined`); una anotación sola no sirve, TypeScript estrecha al valor asignado. `@astrojs/check` no exporta su `package.json`: comprobar con `require.resolve(nombre)`. Un `lucide-react` nuevo puede quitar iconos de marca.
- Temporales fuera del repo: `astro check` (tsconfig `**/*`) y Tailwind recorren todo el árbol; guardar `dist` en `salida/` dentro del repo dio `ENOBUFS` y `ci-verify` ya lo rechaza. Los worktrees de agentes viven en `.claude/worktrees` (dentro del repo): borrarlos al terminar y no ejecutar `typecheck` mientras existan. Tailwind genera reglas con palabras de `specs/` (p. ej. «contents»): cambia el nombre del CSS sin cambiar la web.
- `gh`: `gh run list | cut` truncó el ID del run (usar `--json databaseId`); `gh run watch | tail` oculta su código de salida y un fallo de red sale como 1: mirar el estado del run. El rojo se prueba con rama temporal + PR en borrador (`workflow_dispatch` exige el workflow en `master`).
- RF-4 salió mal la primera vez: un resumen de variantes decía «todo pasa» con un test rojo; el resumen debe listar cada paso (`id` + `toJSON(steps)`). Agentes: verificar sus informes (rama, SHA, diff, test) antes de usarlos (la revisión de la spec 010 acertó 2 defectos reales; los demás eran bajos); el worktree arranca en `master`, no en la rama actual.
